# 数据集与实验设置说明

给合作老师汇报用，内容全部来自代码里能验证的事实（脚本、csv行数），不是转述。

---

## 1. Dataset

### 1.1 数据来源

红外光谱数据来自两个公开来源：

- **NIST**：原始数字化光谱数值文件（`.jdx` 格式，逐点的波数-吸光度/透过率数值），本地 `data/NIST/` 共 **3401** 个文件。
- **SDBS**（Spectral Database for Organic Compounds，日本产业技术综合研究所维护的公开有机物光谱库）：预先渲染好的光谱图片（`.png`），本地 `data/SDBS/` 共 **2359** 个文件。

每个分子对应一行记录，包含 SMILES 结构式 + **118个气味标签**（多标签二分类，如 floral/woody/fruity 等）+ 数据可用性标记（是否有NIST数值、是否有SDBS图）。全部分子的总账表 `data/StandardizedSpectra/all_cleaned.csv` 共 **8503** 行。

### 1.2 图像预处理

统一脚本 `standardize_spectra.py`，把 NIST 数值和 SDBS 原图都转成同一种标准样式：**686×322像素，黑色坐标轴框 + 黑色曲线，白底，无刻度、无文字、无版权信息**。

- **横轴（波数）**：固定 **4000 → 400 cm⁻¹**（从左到右递减，符合红外光谱惯例）。**不是简单线性映射**——采用分段线性，以 2000 cm⁻¹ 为折点：指纹区（400-2000 cm⁻¹）的像素密度是高频区（2000-4000 cm⁻¹）的**2倍**（沿用 SDBS 数据库的传统画法，因为指纹区峰更密集）。NIST 原始数值重绘图和 SDBS 原图现在共用同一套换算公式，两种来源的图可以直接对比/互算像素↔波数。
- **纵轴（强度）**：固定 **0-100 %T**（透过率百分比）。对于本身信号很弱、整条曲线都没跌破50%的气相吸光度数据（GC-IR），会自动按该谱图自身范围拉伸显示（模拟 NIST WebBook 的展示方式，避免曲线看起来"很平"）；有明显深吸收的数据维持固定0-100刻度。
- **送入CNN前**：686×322 统一 resize 到 **224×224**（不保持长宽比，直接拉伸），按 ImageNet 均值/方差归一化。训练时只做轻微的亮度/对比度扰动（`ColorJitter brightness=0.1, contrast=0.1`），**明确不做水平翻转**——因为翻转会颠倒波数方向，物理意义就错了。

## 2. Experiment

### 2.1 数据集划分

项目里其实有两套划分方式，是先后两个实验阶段：

#### （1）legacy（旧划分，随机划分）

最早的实验设置。只用 `all_cleaned.csv` 里 `spectrum_type==1` 的样本（一种已清洗裁剪好的 SDBS 图像子集，共 **2892** 个），**用 `sklearn.train_test_split` 纯随机切成 60/20/20**（`random_state=42`，先切出20%测试集，剩下80%再切出25%作验证集）：

| | 数量 |
|---|---|
| Train | 1734 |
| Val | 579 |
| Test | 579 |

"随机划分"指的就是这里——不考虑分子结构相似度、不考虑数据来源（图是NIST重绘的还是SDBS原图），纯按行号随机抽。这样切分的问题是：同一种绘图风格、甚至结构相近的分子，可能同时出现在train和test里，存在**隐性的信息泄漏**风险，可能会虚高测试集上的表现。

#### （2）nist_split（新划分，按数据来源划分）

后来设计的对照实验，专门用来检验上面这个泄漏风险。核心思路：**训练集只用有原始NIST数值的分子（重绘图），测试集只用没有NIST数值、只有现成SDBS图的分子**——刻意制造训练/测试之间的绘图风格差异，更接近真实的域外泛化场景：

- **Train**：1659个分子来自"有可用NIST数值"（jdx文件存在且单位可解析），用数值重新画图；其中1126个分子恰好也有现成SDBS图，多拿到一张SDBS图作为增强样本 → 实际训练样本 = 1659 + 1126 = **2785**
- **Val / Test**：候选池是"没有可用NIST数值、但有SDBS图"的分子，用**多标签分层抽样**（`iterstrat`，保证118个标签在val/test里的正例分布尽量均衡）随机对半切分（`seed=42`）→ Val **616** / Test **617**
- **Excluded**：两边都没有（既没NIST数值也没SDBS图）的分子，**5611**个，不参与任何实验

| | 数量 | 图像来源 |
|---|---|---|
| Train | 2785（1659原始+1126增强） | NIST数值重绘为主 |
| Val | 616 | 纯SDBS原图 |
| Test | 617 | 纯SDBS原图 |

即：**Phase 5 对比的"旧划分 vs 新划分"，本质是"同来源风格随机混切" vs "训练用NIST重绘图、测试用纯SDBS原图的强制域外泛化"**。已经跑出的对比结果见 [phase5_split_comparison.md](phase5_split_comparison.md)：4个backbone里，resnet50/resnet101在新划分下F1明显下降（支持"旧划分有泄漏"的假说），vgg16反而相反，vit_b两边都很差看不出方向性——不是全面支持假说，还有开放问题没深挖。

### 2.2 区域重要性（2D Grad-CAM）

目前 `gradcam_aggregate.py` 产出的是**1D波数曲线**：把每张图的Grad-CAM热力图沿波数轴坍缩（每一列取最大激活）再换算成波数，得到"某个气味标签平均关注哪个波数"，丢失了图像上下方向（曲线峰顶vs峰谷vs基线）的信息。

已经新写了一个脚本 `experiments/gradcam_region_map.py`，**保留完整的二维空间结构**：对每个气味标签，把测试集里全部正例样本的Grad-CAM热力图（224×224，逐像素）取平均，叠加在这些样本的平均光谱图背景上，输出"模型看这个气味标签时，图像上哪一片区域平均被关注"的热力图——和1D曲线是互补关系。

**这部分还没有实际结果**——需要在有 `checkpoints/resnet101_pretrained/best.pth`（或 `checkpoints/resnet101/best.pth`）的服务器上跑：

```bash
cd experiments
python gradcam_region_map.py --exp resnet101_pretrained --min_pos 10   # 新划分(nist_split)
python gradcam_region_map.py --exp resnet101 --min_pos 10             # 旧划分(legacy)
```

结果存在 `results/{exp}/gradcam_region_map/`：每个达标标签一张热力图 + 一张 `_grid.png` 汇总网格图，方便一次性看全部标签。跑完把这两个目录传回来，我把图嵌进这份报告里。
