## 2. 回答您的两个疑问

### 疑问1：训练集固定，验证/测试是否随机？旧的纯图片方案是否三者随机分配？

看了 `experiments/train.py`：**旧方案是全随机**——把全部2892张标准化图片（SDBS来源和NIST重绘混在一起，不区分）用 `sklearn.train_test_split(random_state=42)` 做 60% / 20% / 20% 的 train/val/test 三向随机切分，完全没有按来源分层。也就是说旧实验里，测试集中很可能混有NIST重绘的图，训练集里也混有SDBS的图，来源是"打散"的。

新方案下，**训练集来源是确定性的**（= 有NIST原始数据的分子，不随机），**验证/测试的候选池也是确定性的**（= 没有NIST原始数据、只有SDBS图的1206个分子）。但这1206个分子内部具体谁进验证、谁进测试，仍然需要一次随机划分——这个我建议：

- 固定 `random_state=42`（延续旧实验的习惯，方便文档间可比）
- 建议验证:测试 = 1:1（各约603个），而不是旧的 20%/20%（因为现在分母是1206而不是2892，具体数值会不同，但比例延续）
- 如果要更严谨，可以做多标签分层抽样（保证每个气味标签的正例尽量均匀落在验证/测试两边，避免小类目标签全被分到一边导致AUC算不出来）——`iterstrat` 库的 `MultilabelStratifiedShuffleSplit` 可以做到，比纯随机稳。**这点我会默认采用分层，如果您不需要这么复杂，普通随机也可以，请告知。**

### 疑问2：重合的1153个分子怎么利用？

两个用法都值得做，而且互不冲突：

**用法A —— 训练集数据增强（免费多样本）**
这1153个分子的训练版本本身用NIST jdx重画+算数值向量；但既然 StandardizedSpectra 里已经有它们的SDBS版本图片（同一分子，不同测量来源，曲线会有细微差异），可以把这些SDBS版本图片也作为"同分子的第二个视角"追加进训练集（标签不变，数值向量仍然只用NIST那一份，因为SDBS没保留原始数值）。**因为这1153个分子全部落在训练池里、不会出现在测试/验证池，所以这样做不会造成训练/测试信息泄漏，是安全的增强手段**，对小样本问题有直接帮助。会在数据里加一列 `source` 区分 `nist_original` / `sdbs_paired_aug`，方便后续做"加不加这个增强"的消融对比。

**用法B —— 跨来源一致性分析（服务于要求里"结果分析2"）**
同一分子有两份独立测量的光谱（SDBS版 vs NIST重绘版），可以专门做一个小实验：分别喂给训练好的模型，看预测概率是否稳定、Grad-CAM/attention 关注的波数区间是否稳定。如果稳定，说明模型学到的是"分子真实的光谱特征"而不是"某个来源特有的绘图噪声/伪影"，这对论文里论证"光谱确实提供了可靠的增量信息"是很有力的证据。这个实验用**训练集内部**的1153个重合分子做即可，不需要额外候选，成本很低。

│   ├── vectors/{file_id}.npy       # 400-4000 cm-1 定长向量（与图像同源、同一套 y 轴变换）

### 3.2 训练图像重绘规则

对训练池里的全部分子（1659个，实测数字，见Phase 0结果 + 1126个重合分子的SDBS增强图 = 训练图片总数2785张，其中1659张有对应的数值向量），**统一用 `process_nist` 的画法重新渲染**，不复用 StandardizedSpectra 里已存在的图（哪怕是同一分子的NIST-only版本也重新画一遍，保证整批训练图片处理逻辑完全一致，不会有"一部分是老脚本某个历史版本画的"这种不一致风险）。

顺手修复的小bug：`process_nist` 里 `xunits != '1/CM'` 的判断要放宽，接受 `'CM-1'`（带连字符）这个等价写法，否则会白白扔掉2个可用样本（已修复）。

#### 3.2.1 重要发现并已修复：SDBS图的X轴不是纯线性的

Phase 1跑完后核对NIST重绘图和SDBS图（同一分子两个来源）的峰位置，发现对不上，用同一分子的真实峰位（从jdx原始数值确认）反推后发现：**SDBS的图（type1和type2都一样）在2000 cm⁻¹处有个折点，折点以下（400-2000，指纹区）的像素密度是折点以上（2000-4000）的整整2倍**——这是SDBS自己几十年的历史画图惯例（指纹区峰密集，故意画宽），在多个样本上反复验证、稳定复现，不是个例噪声。而 `process_nist` 原来用的是matplotlib默认的纯线性轴（`ax.set_xlim(4000,400)`），和SDBS图看似"同样标注4000→400"，实际像素↔波数的换算关系完全不同。

**已按此修复**：`standardize_spectra.py` 新增 `wavenumber_to_pixel()` / `pixel_to_wavenumber()` 两个函数，实现和SDBS一致的分段线性映射（折点2000 cm⁻¹，折点以上7.58 cm⁻¹/px，折点以下3.79 cm⁻¹/px，折点像素位置263.85/686≈38.5%），`process_nist` 画图前先用这个函数把原始波数warp成像素坐标再画。这是无损操作——NIST是原始数值点，warp只改"画在哪一列"，不改点的顺序、不改%T值、不丢失/合并任何原始数据点。

**没有改的部分**：
- SDBS原图、SDBS增强图（`images_aug/`）、val/test图——原本就是分段轴，不用动
- 数值向量（`vectors/`）——按波数直接分bin，不经过图像像素，和X轴是纯线性还是分段无关，不受影响（详见3.3节末尾说明）

修复后用同一分子（file_id=4）验证：NIST重绘图和SDBS图的两个主峰（真实波数2960、1720 cm⁻¹）现在分别落在wn=2961.5和1726.5 / 2961.5和1711.4，误差在15 cm⁻¹以内（修复前误差高达300-500 cm⁻¹）。1659张训练图已用新公式重新生成。

以后任何"图像像素位置→波数"的换算（比如Phase 4的Grad-CAM分析），全部图片（不分NIST重绘还是SDBS来源）统一用 `pixel_to_wavenumber()` 这一套公式即可，不需要再区分来源。

### 3.3 数值向量生成规则（与图像严格同源）

沿用 `docs/research_plan.md` 里"方案A"的思路：

1. 400–4000 cm⁻¹ 切成 N 个等宽 bin（建议 N=360，即每 bin 10 cm⁻¹，和研究计划保持一致，也可以配置成 90/180 做消融）
2. 每个 bin 取该区间内 %T 的最小值（吸收最深处）
3. **关键约束**：这一步用的 y 轴变换必须和 `process_nist` 画图时完全一致，包括气相拉伸逻辑——即 `YUNITS=ABSORBANCE` 且整条曲线 `y_min > 50` 时，按该谱图自己的范围重新拉伸到接近 0-100（复用现有代码里那段 `margin = (100 - y_min) * 0.05` 的逻辑），液相/固相（`TRANSMITTANCE`）维持固定 0-100。
   这个"严格同源"是后面"图像重要区域 vs 数值重要区域对比"实验能成立的前提——如果图像和向量用了两套不同的y轴缩放，对比就没有意义了。

**注意"严格同源"只针对Y轴（%T的气相拉伸变换），不针对X轴。** 向量按波数区间直接分bin（400-410、410-420...），不经过图像像素，所以3.2.1节提到的"SDBS图X轴是分段线性、NIST重绘图后来也改成分段线性去匹配它"这件事，跟向量完全无关——向量的bin一直是、也应该一直是按波数均匀切分，不需要跟着图像的像素分段规则走（序列模型RNN/LSTM/GRU/Transformer也更适合吃均匀间隔的输入）。两边通过各自的"索引→波数"换算公式（图像用`pixel_to_wavenumber()`，向量用`bin_idx*10+400`的简单线性）都能换算到同一条波数轴上做比较，不需要内部索引方式一致。

#### 3.3.1 覆盖缺口的处理：填充值 + 显式掩码

实测过全部1697个NIST jdx文件的真实 `FIRSTX`/`LASTX`，发现原始数据并不严格铺满400-4000：89%的谱图实际测量下限高于400（常见从450-600才开始），67%上限不到4000，另有26%（445个，其中38个到了近红外~7500 cm⁻¹）测量范围超出4000。整体在400-4000窗口内的覆盖率中位数94.4%，多数文件缺口不大，但低波数端（接近400那侧）缺口的确普遍存在。

因此每个bin除了%T值本身，**额外生成一份等长的0/1覆盖掩码**（1=该bin范围内有真实测量点，0=超出该谱图实际测量范围/纯填充）：

- **%T值的填充**：缺失bin填 100（代表"无吸收/空白"），这和图像上同一区域的视觉效果一致（`process_nist` 画图时，matplotlib对没有数据的x范围不会画线，画布留白，视觉上约等于%T=100那条线贴着顶部/看不见），保证数值向量和图像分支看到的是同一件事。
- **不用NaN**：大部分层（Conv1d/RNN/Linear）不能直接处理NaN，还要额外写分支逻辑，不如显式掩码干净。
- **不做边界外推**：把边界处的真实测量值延伸填充到缺口里，容易在边缘造出一条实际不存在的"假平线"，如果后续Grad-CAM/attention分析把这段当成重要区域，会污染"图像区域 vs 数值区域一致性"这个实验的结论。
- **为什么必须显式标记，不能只填100完事**：89%的谱图在450-600以下都填了100，如果不加掩码，模型很容易把"仪器量程覆盖不到"这个采集伪影当成"分子在低波数没有吸收"的化学规律来学，这个偏差覆盖了近九成训练样本，不是可以忽略的小问题。

掩码在两个分支里的具体接法：
- **Transformer 分支**：掩码就是标准的 attention padding mask，直接复用 `docs/network_architecture.md` 里 Peak Token Transformer 已经设计好的 padding_mask 机制。
- **RNN/LSTM/GRU 分支**：没有Transformer那种"跳过某一步"的机制，做法是把掩码位当成每个时间步的第二个输入维度（`[%T值, 是否真实测量]`），让模型自己学会降权被标记为缺失的位置。
- **5.2节"图像区域 vs 数值区域一致性"分析**：算相关系数时只用两边都有真实数据覆盖的bin，被掩码标记为缺失的bin要剔除——否则"模型正确地避开了假填充区"会被误读成一个化学发现。

`vectors/{file_id}.npy` 建议存成形状 `[N, 2]`（第0列%T值，第1列覆盖掩码），而不是两个分开的文件，方便一次性加载。

### 3.4 验证/测试图片处理

不做任何重新处理，直接从 `data/StandardizedSpectra/images/{file_id}.png` 拷贝过去。这部分从始至终没有原始数值数据，所以验证/测试阶段的"方法3"（融合模型）天然无法在这部分数据上使用数值分支——这也是为什么训练集必须是"有原始数据的分子"的原因：融合模型需要在训练时学会怎么用数值信息，但在测试NIST覆盖不到的新分子时，只能退化成纯图像模型来打分（或者干脆在方法3的测试阶段只报告"图像单分支"和"双分支"两种输出模式的对比）。这一点会在后续"方法3怎么在没有数值数据的测试集上评估"里详细说明，也请您留意——**融合模型在测试集上事实上只能吃图像分支**，这是数据本身决定的，不是设计缺陷。

### 3.5 实验产出存放规则：权重与结果分开

因为训练都在云端服务器上跑，模型权重文件体积大没必要传回本地，所以所有新实验（方法1/2/3）沿用刚刚在旧 backbone 实验里落地的约定，`checkpoints/` 和 `results/` 分开：

```
experiments/
├── checkpoints/{实验名}/best.pth      # 权重，体积大，留在服务器，不传回本地
└── results/{实验名}/
    ├── history.csv                     # 每 epoch 指标
    ├── test_result.csv                 # 测试集最终指标

```

跑完实验只需要把整个 `results/` 目录打包传回本地就有全部指标、日志和可视化图，`checkpoints/` 留在服务器上供后续 Grad-CAM/attention 分析直接读取即可。`{实验名}` 按方法区分，比如 `resnet101_pretrained` / `resnet101_scratch`（方法1/2）、`transformer_7layer`（方法3的某个组合），避免和旧的四个 backbone 实验目录混在一起。

## 4. 三种训练方法设计

### 方法1 / 方法2 —— 预训练 vs 从零训练消融（已与您确认）

在新划分（`NistSdbsSplit`）上，对 VGG16 / ResNet50 / ResNet101 / ViT-B 各跑两次：
- 方法1：不加载 ImageNet 预训练权重，随机初始化从零训练
- 方法2：加载 ImageNet 预训练权重训练（即现有 `train.py` 的默认行为）

需要给 `train.py` 的 `build_model` 加一个 `--pretrained/--no-pretrained` 开关（目前是硬编码 `weights=xxx_Weights.IMAGENET1K_V1/V2`），并把 `DATA_ROOT`/`CSV_PATH` 指向新的 `NistSdbsSplit`，划分逻辑从"读CSV随机切三份"改成"读 `manifest.csv` 里的 `split` 列直接分组"（不再用 `train_test_split`）。

一共 4 backbone × 2 初始化 = 8 次训练。

### 方法3 —— 原始数据 + 图片融合模型（RNN / LSTM / GRU / Transformer，深度 3/7/9 层）

结构复用 `docs/network_architecture.md` 的 Fusion 思路，两个分支：

```
Image branch:    CNN backbone (建议 ResNet50，可选预训练) → image_emb [B, 256]
Sequence branch: 数值向量 [B, 360] → 序列建模 (RNN/LSTM/GRU/Transformer, 层数可选3/7/9) → seq_emb [B, 256]
Fusion:          concat([image_emb, seq_emb]) → Linear → MultiLabelHead → 120维 sigmoid
```

序列分支的输入怎么"变成序列"：把360维向量看作长度360、每步1个标量的序列（可选：切成若干patch，比如每10个bin一组，序列长度36，每步10维，减少序列长度、降低RNN类模型的梯度问题）。Transformer 分支类似 `docs/network_architecture.md` 里 Peak Token Transformer 的做法，但这里是等间隔bin token而不是峰token。

**需要和您确认的规模问题**：RNN/LSTM/GRU/Transformer 四种架构 × 3种深度 = 12个组合，训练集只有约1657-2810个样本，12个模型全跑一遍工作量不小（而且深模型如7层/9层LSTM在这个样本量下大概率会过拟合）。**建议先每种架构跑一个较浅的深度（比如都先跑3层）建立基线，看效果和过拟合情况，再决定是否值得把7层、9层也跑满**——避免一上来就跑12个组合但一半都没意义。这只是执行顺序建议，最终跑几个组合您可以随时定。

## 5. 结果分析设计

### 5.1 Grad-CAM 按气味类别聚合，寻找规律

现有 `experiments/grad_cam.py` 只做单样本可视化。需要新增一个聚合脚本：对测试集里某个气味标签的全部正例样本，把各自的 Grad-CAM 热力图（686像素宽，对应4000→400 cm⁻¹）在同一坐标系下取平均/叠加，画出"该气味标签最敏感的波数区间"曲线——这正对应 `docs/research_plan.md` 里提到的 "Peak importance map"。可以对全部118个标签批量产出，横向比较不同气味类别的敏感区域差异。

### 5.2 图像重要区域 vs 原始数据重要区域是否一致

- 图像侧：Grad-CAM 在686px横轴上的激活分布，用 `standardize_spectra.py` 里的 `pixel_to_wavenumber()` 换算成波数（**分段线性**，2000cm⁻¹为界，不是简单的4000-400线性映射——这是3.2.1节发现并修复的问题，NIST重绘图和SDBS来源图现在共享同一套换算公式，不需要再区分来源）。
- 数值侧：融合模型（方法3）里序列分支的重要性——Transformer 用 attention 权重，RNN/LSTM/GRU 用积分梯度（Integrated Gradients，可以用 `captum` 库）——这部分本身就是按360个bin索引，直接对应波数区间，不需要额外换算。
- 两边都换算到同一条 400-4000 cm⁻¹ 横轴后，可以画出对照图，也可以算 Pearson/Spearman 相关系数做定量对比。**这一步依赖方法3训练出来的融合模型，所以必须排在方法3跑完之后。**

### 5.3 新旧数据集划分方法对比

同一个backbone（建议用效果最好的 ResNet101）分别在"旧的纯随机划分"和"新的NIST/SDBS来源划分"上训练，对比 Test Macro-F1 / Macro-AUC。预期新划分会更难（测试集分子的来源、绘图风格和训练集完全不同，更接近真实的域外泛化场景），如果确实变难，这本身就是论文里一个很好的讨论点："旧的随机划分可能因为同分子/同来源风格在train和test里都出现过，存在隐性的来源信息泄漏，虚高了性能"。
